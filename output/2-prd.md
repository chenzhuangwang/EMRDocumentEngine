# 产品需求文档 (PRD) - 文档编辑器引擎

> 版本: v2.0 | 日期: 2026-07-28 | 阶段: docs (重构更新)
>
> **v2.0 变更**: 文档模型重构为 ModelD 树形结构，支持医疗数据元编码 (HDSD/DE)

---

## 1. 产品愿景

构建一个**通用的结构化文档编辑器引擎**，提供与 Word 一致的所见即所得排版体验，支持结构化数据录入、复杂表格、精确打印和多人协作。以电子病历为核心场景，可扩展至合同文书、政府公文、金融表单等结构化文档领域。

### 1.1 产品定位

一款**纯前端 Canvas 渲染 + Java 后端的结构化文档编辑引擎**，具备：
- Word 级别的所见即所得排版能力
- 超越 Word 的结构化数据录入与绑定能力
- 工业级的打印精度与多格式导出能力
- 多级权限内容管控与全链路审计能力

### 1.2 核心差异化

| 对比维度 | 传统富文本编辑器 | 本引擎 |
|----------|-----------------|--------|
| 渲染方式 | DOM/contenteditable | Canvas + 自研排版引擎 |
| 跨浏览器一致性 | 差 | 像素级一致 |
| 分页精度 | 不可靠 | 精确分页 |
| 文档模型 | 扁平 HTML/DOM | **树形 DocumentTree (ModelD)** |
| 结构化录入 | 不支持 | **SmartTextNode + HDSD/DE 国标编码** |
| 权限粒度 | 无 | 多级权限 + 留痕 |
| 打印质量 | 一般 | 专业级精确打印 |

### 1.3 ModelD 树形文档模型

v2.0 核心升级：从扁平 `IElement[]` 数组重构为树形 `DocumentTree`，天然映射到医疗文档的层级结构：

```
DocumentTree
└── pages: Page[]
    ├── header: BlockNode[]
    ├── body: FlowBody
    │   └── children: BlockNode[]
    │       ├── Paragraph → children: InlineNode[]
    │       │   ├── TextNode        (普通文本, 含 TextStyle)
    │       │   └── SmartTextNode   (结构化字段, 含 ElementMeta)
    │       └── Table → TableRow[] → TableCell[] → BlockNode[] (支持嵌套)
    └── footer: BlockNode[]
```

每个 `SmartTextNode` 内嵌 `ElementMeta`，携带医疗国标编码：
- `code.internal` — HDSD 医院内部编码 (如 "HDSD00.12.132")
- `code.dataElement` — DE 国标数据元编码 (如 "DE07.00.007.00")
- `format` — 数据类型约束 (S1/S3/N/D) 与校验规则

## 2. 目标用户

### 2.1 主要用户角色

| 角色 | 核心需求 | 使用频率 |
|------|----------|----------|
| **文档编写者**（医生/文员）| 快速录入、格式化、打印 | 每天 8+ 小时 |
| **模板设计者**（管理员）| 设计结构化模板、配置校验规则 | 每周 |
| **审核者**（上级/质控）| 查看、批注、修改留痕、质控检查 | 每天 |
| **系统集成者**（开发者）| API 调用、数据交换、系统集成 | 按需 |

### 2.2 核心场景

1. **新建文档**：选择模板 → 填写结构化字段 → 自由文本补充 → 保存/打印
2. **编辑已有文档**：打开文档 → 修改内容 → 自动留痕 → 保存
3. **模板设计**：创建空白模板 → 拖拽控件布局 → 配置绑定规则 → 发布模板
4. **质控审核**：打开待审文档 → 逐项检查 → 批注/修改 → 通过/驳回
5. **批量处理**：选择多份文档 → 批量导出 PDF → 批量打印
6. **多人协作**：多人同时编辑 → 实时同步 → 冲突合并

## 3. 功能需求

### 3.1 MVP（最小可行产品）功能清单

#### F1: 文档基础编辑
- F1.1 文本录入与编辑（键盘、粘贴）
- F1.2 文本格式化（粗体、斜体、下划线、删除线、上下标）
- F1.3 字体设置（字体名称、字号、颜色、背景色、高亮）
- F1.4 段落设置（对齐方式、行间距、段落间距、缩进）
- F1.5 无限制 Undo/Redo（至少 100 步历史）

#### F2: 文档分页系统
- F2.1 精确分页（A4 默认，可配置纸张大小）
- F2.2 页眉/页脚（首页可独立设置）
- F2.3 页码（多种数字格式，可显示当前页/总页数）
- F2.4 页边距设置（上下左右）
- F2.5 分页视图 / 连续视图切换

#### F3: 文档元素
- F3.1 表格（创建、编辑行列、合并拆分单元格）
- F3.2 图片（插入、拖拽调整、文字环绕）
- F3.3 换行/分页符
- F3.4 分隔线

#### F4: 文档存储
- F4.1 文档以 JSON 格式存储到后端
- F4.2 文档列表（创建、查看、编辑、删除）
- F4.3 自动保存（定时 + 失焦保存）

#### F5: 模板系统
- F5.1 模板创建与保存
- F5.2 从模板新建文档
- F5.3 模板分类管理

#### F6: 打印与导出
- F6.1 打印预览
- F6.2 PDF 导出
- F6.3 HTML 导出
- F6.4 数字水印（文本/图片水印, 平铺/居中, 透明度/旋转角度可配）
- F6.5 多格式导入（JSON 原生 / HL7 CDA XML / HTML 富文本 / Markdown 轻量录入, 自动格式检测）

### 3.2 P1 增强功能

#### F7: 结构化表单控件
- F7.1 文本输入框（占位符、固定宽度、字符限制）
- F7.2 下拉选择框（单选/多选、数据源绑定）
- F7.3 日期选择器
- F7.4 复选框 / 单选框
- F7.5 数字输入框（范围限制）

#### F8: 数据绑定
- F8.1 JSON 数据源绑定到控件
- F8.2 表格动态行扩展
- F8.3 字段级联（可见性表达式）

#### F9: 数据校验
- F9.1 必填项检查（基于 SmartTextNode.element.required）
- F9.2 正则表达式校验（基于 SmartTextNode.element.format）
- F9.3 数值范围校验
- F9.4 字符串长度校验（minLength / maxLength）
- F9.5 校验结果可视化提示（红色边框 + tooltip 错误信息）

#### F10: 医学质控引擎
- F10.1 完整性校验：基于模板定义，检查所有必填字段是否已填写
- F10.2 逻辑一致性校验：跨字段逻辑规则（如 "出院日期 >= 入院日期"、"收缩压 > 舒张压"）
- F10.3 规范性校验：医学编码/术语是否符合 ICD/SNOMED 等标准
- F10.4 质控评分：加权计分模型，量化文档质量（完整度 40% + 一致性 30% + 规范性 30%）
- F10.5 质控规则注册：通过 SmartTextNode.element.code (HDSD/DE) 关联校验规则
- F10.6 质控结果面板：错误/警告/通过 三级分类，可点击定位到对应字段
- F10.7 质控审核流程：质控员审核 → 通过/驳回/修正 状态流转

#### F11: 权限与留痕
- F10.1 三级权限等级（创建者 > 编辑者 > 只读者）
- F10.2 修改留痕（新增/修改/删除标记不同样式）
- F10.3 留痕模式 / 清洁模式切换
- F10.4 操作审计日志

#### F12: 文档批注
- F11.1 创建批注（选中文本 → 添加批注）
- F11.2 批注列表与定位
- F11.3 批注回复
- F11.4 标记批注为已解决

### 3.3 P2 高级功能

#### F13: 多人实时协作
- F12.1 多人同时编辑同一文档
- F12.2 实时同步修改内容
- F12.3 编辑人光标位置显示
- F12.4 冲突自动合并

#### F14: 版本管理
- F13.1 文档版本历史
- F13.2 版本对比（差异高亮）
- F13.3 版本回滚

#### F15: 高级元素
- F14.1 条形码 / 二维码
- F14.2 LaTeX 数学公式
- F14.3 图表（柱状图/折线图/饼图）

#### F16: AI 能力
- F15.1 AI 智能文档生成
- F15.2 AI 内容校对与纠错

#### F17: 多格式导出

## 4. 非功能需求

### 4.1 性能
- 文档加载：< 1 秒（10 页文档）
- 百页文档秒开（参考 DCWriter 5.0 基准）
- 分页计算：增量计算，不阻塞 UI
- 打印：50 页文档 < 3 秒
- 自动保存：< 200ms 响应

### 4.2 兼容性
- 浏览器：Chrome 90+, Firefox 90+, Edge 90+, Safari 15+
- 分辨率：支持 1080p / 2K / 4K 高清屏
- 系统：Windows、macOS、Linux

### 4.3 可用性
- 所有编辑操作支持键盘快捷键
- 工具栏与右键菜单双入口
- 编辑操作即时有视觉反馈

### 4.4 安全性
- JWT 认证 + 接口鉴权
- 文档级别权限控制
- 操作日志不可篡改
- XSS/SQL 注入防护

### 4.5 可扩展性
- 插件式元素注册机制
- 自定义控件开发接口
- 第三方系统集成 API（RESTful + WebSocket）

## 5. 用户故事

### US-01: 新建并编辑文档
> 作为文档编写者，我希望能选择一个模板新建文档，在表单区域快速填写结构化数据，在自由文本区域书写内容，最后保存或打印文档。

**验收标准：**
- [ ] 能从模板列表中选择模板新建文档
- [ ] 结构化区域只能录入指定格式内容
- [ ] 自由文本区域可以富文本编辑
- [ ] 点击保存后文档持久化到后端
- [ ] 点击打印后弹出打印预览

### US-02: 模板设计
> 作为模板设计者，我希望能在空白文档上拖拽放置各种控件（输入框、下拉框、表格等），配置数据绑定规则和校验规则，并保存为可复用的模板。

**验收标准：**
- [ ] 设计模式下可以插入任意类型元素
- [ ] 控件属性面板可以配置校验规则
- [ ] 可以配置数据源绑定路径
- [ ] 保存后模板出现在模板列表中

### US-03: 修改留痕
> 作为审核者，我希望查看文档时能清楚看到做了哪些修改（新增、删除、修改），并能切换留痕模式和清洁模式。

**验收标准：**
- [ ] 新增内容以特定颜色下划线标记
- [ ] 删除内容以删除线标记但不移除
- [ ] 清洁模式下隐藏所有修改标记
- [ ] 留痕信息包含修改人和时间

### US-04: 数据校验
> 作为文档编写者，我希望能实时看到哪些必填项还没填、哪些字段值不合法，防止提交不合格的文档。

**验收标准：**
- [ ] 未填的必填项以红色边框提示
- [ ] 校验失败的字段显示错误信息
- [ ] 所有必填项完成后状态指示器变绿

### US-05: 医学质控
> 作为质控员，我希望能对病历文档进行完整性、逻辑一致性、规范性检查，获得质控评分，并对不合格文档提出修改意见。

**验收标准：**
- [ ] 质控面板显示错误/警告/通过三级分类结果
- [ ] 点击质控结果可定位到对应字段
- [ ] 质控评分实时更新（编辑后重新计算）
- [ ] 支持自定义逻辑校验规则（如 "出院日期 >= 入院日期"）
- [ ] 质控审核流程：审核→通过/驳回/修正 状态可流转
