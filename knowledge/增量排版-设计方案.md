## 2. 目标与非目标

### 目标

1. 单字符编辑的成本从 `O(全文字段落)` 降到 `O(脏段落 + 受影响页)`。
2. **正确性判据**：任意编辑序列之后，增量结果与全量结果**逐字节相同**（SLIF 深度序列化比较，含 pageIndex/items/几何）。
3. 失效规则可枚举、可测试；宁保守，不猜。
4. 开关可关闭：`Draw.recomputeLayout` 能退回全量，用于对比与线上回滚。

### 非目标

- 不改渲染层与粒子管线。
- 不做内存淘汰策略（`MemoryManager` 另议）。
- 不做后台排版/Worker（后续可单独立项）。
- 不改变 SLIF 数据结构与导出结果。

## 3. 设计

### 3.1 布局单元与缓存键

段落是唯一布局单元。一个段落的排版结果 = `ILine[]` + 总高 + 列表编号上下文。

缓存键必须覆盖「段落自身内容 + 子节点内容 + 结构位置」：

```
key(paraId) = hash(
  pool.structureVersion,          // 任何 children 增删/移动
  pool.getNodeVersion(paraId),    // 段落样式变化
  for child in para.children:     // 文本子节点
    child.id + pool.getNodeVersion(child)
) + 可用宽 + 修订显隐 + 列表标记 + 图片尺寸摘要
```

- `NodePool` 的版本号只在**被更新节点自身**上自增（L220-228），不会向父节点冒泡 —— 所以必须聚合子节点版本，不能只读段落版本。
- `structureVersion` 是全局计数（任何结构变更都变），用它做保守失效：结构编辑会让全部段落缓存失效，但结构编辑远少于打字。
- 列表编号是跨段状态：布局**先算标记、再查缓存**，标记进键 —— 前序段落变化导致编号重排时，后续段落的键自动变化（见等价性随机用例）。
- 图片行元素只取节点自身的尺寸/环绕方式；脚注引用的编号在分页后的 Step 4 回填，不参与断行 —— 二者都可缓存。控件/域/交叉引用的显示值来自段落之外，仍不缓存。
- 缓存值只存**段落内**结果（行元素、行高），不存页码 —— 页码由分页阶段重新推导。

### 3.2 失效规则

| 变化 | 失效范围 | 理由 |
|---|---|---|
| `InsertText` / `DeleteRange`（段内） | 该段落 + 其后分页 | 影响行数与总高 |
| `SplitParagraph` / `MergeParagraph` | 两段 + 其后分页 | 结构变化 |
| `ParagraphStyleCommand` | 该段落 + 其后分页 | 缩进/行距/列表改变行宽与行高 |
| `FormatTextRangeCommand` | 该段落 + 其后分页 | 字号/字体改变行高 |
| 表格内编辑 | 该 cell 所属表格块 + 其后分页 | 表格分页以块为单位 |
| 页眉页脚/页边距/纸张 | **全量** | 版心与页高改变，所有行宽失效 |
| 域代码 `PAGE` / `NUMPAGES` | **全量** | 总页数变化会改预留宽（`FieldReserveContext.totalPagesHint`） |
| 脚注增删 | **全量** | 增删引用是结构编辑，全部段落键失效；脚注区预留本身是全文常数 |
| 脚注所在段落之后的正文编辑 | 该段落 + 其后分页 | 复用页脚注区保留；新页编号由 `seedFrom` 播种接续 |
| 列表编号 | 该列表后续同列表段落 | 编号是跨段落状态 |
| 计算值/时钟变化 | 含控件段落 + 全部表格块 | 代次 `#cv` 只进**含控件**段落键与表格键；纯文本段落不失效 |
| 模板定义（controlType/label/prefix/suffix）变化 | 含控件段落 + 全部表格块 | 版本 `#tv` 同上（定义不进节点版本） |
| `invalidation === 'none'` | 跳过排版 | 契约承诺无 reflow；先加断言测试再启用 |

无法证明安全的场景一律升级为全量 —— 这比错排更容易发现和回滚。

### 3.3 分页重算

1. 用缓存重建段落 → `ILine[]` 流（只重算脏段落）。
2. 找到**首个受影响页**：`PageStartTable` 记录「页 → 起始段落」，取所有脏段落中的最小页。
3. 从该页起始段落重新跑 `PageBreaker`，保留之前页面的 SLIF 对象。
4. 页码变化若影响域代码预留宽（`representativeFieldText`），触发一次全量修正 —— 与现有 `fullLayout` 的两轮策略一致。

### 3.4 接线点（M2a + M2b 已落地）

```
CommandManager.execute
  → patch.invalidation + dirtyNodeIds
  → document:changed
  → Draw.recomputeLayout(pool, invalidation)
      → LayoutEngine.fullLayout(doc, pool, invalidation)
          ├─ 段落行缓存: 键命中 → 复用 ILine[]（跳过元素构建与断行）
          ├─ canIncrementalPagination(invalidation, 文档子集) ?
          │    ├─ reuse-all → 页面整份复用（没有任何行变化）
          │    ├─ resume     → 前序页复用 + 从「首个重算段落的前一页」续排
          │    └─ 否则        → PageBreaker 全量
          └─ 提交页起始行表 + 段落→页表（PageStartTable）
  → HitTestIndex.rebuild(pages)   // 仍全量（下一步）
```

剩余：`HitTestIndex` 按页重建；`DirtyTracker` 的 `dirtyNodeIds` 尚未用于
"哪些段落重算"的判定（当前以缓存未命中为准，语义等价且无需信任命令声明）。

## 4. 验收

### 4.1 等价性（硬门）

- `IncrementalLayoutEquivalence.test.ts`：固定种子随机编辑，持久引擎 vs 全新引擎，SLIF 规范序列化后**逐字节比较**（各 300 步；含结构编辑、样式编辑与列表开关）。
- `IncrementalPagination.test.ts`：分页场景 120 步随机编辑（文本/对齐/长文本/截断），每步逐字节对照，并断言至少一次 `resume`。
- 定向用例：首段编辑、结构改动、页数变化、含行内图片、修订开关、控件不缓存、列表编号重排；表格：内容不变整份复用、表格后编辑续排、cell 编辑从表格起始页重排、跨页表格后的编辑回退到表格起始页、cell 内非文本叶节点回落全量、计算值代次变化使表格键失效、两张跨页表格 60 步随机对照；脚注：脚注后的正文编辑续排、复用页之后的新脚注编号接续、新增引用回落全量；同形状补丁：中段/首段/跨页多行段落、关掉开关的对照、100 步随机同长度替换、脚注与表格文档不走补丁、Draw 接线（命中索引起点与尾部复用页可命中）。
- 任何不一致即失败，不允许用「视觉一致」替代。设计文档原定的 500 步按 300+120 步落地；加长序列是后续回归项，不是放松判据。

### 4.2 性能（软门，记录不设卡）

实测（jsdom，2026-10-19；绝对值偏慢，看比值）：

| 场景 | 全量 | 增量 | 比值 |
|---|---|---|---|
| 1000 段 / 33 页，连续 30 次单字编辑 | 15006.8 ms（≈500 ms/次） | 687.7 ms（≈23 ms/次） | **4.6%**（约 21.8×） |
| 首次布局（纯文本） | 800.0 ms | 608.5 ms | 76%（首次不额外付费） |
| 500 段 + 150 行表格 / 21 页，10 次编辑（正文与 cell 交替） | 2714.5 ms（≈271 ms/次） | 156.9 ms（≈16 ms/次） | **5.8%**（约 17.3×），平均复用 8.5/21 页 |

- 典型一次中段编辑：`resume`，复用 18/33 页；段落缓存命中 ≈ 30:1（30970 命中 / 1030 未命中）。
- 表格用例（2026-10-20）：正文编辑复用脏段之前的页；cell 编辑把表格记入重算，但表格**之前**的页照常复用，故平均复用页数取决于表格位置。
- **M2e 同形状页补丁（2026-10-20）**：中段单字编辑（行数/行高/段末标记都不变）只重建所在页，尾部页对象原样复用。jsdom 实测中段编辑：500 段 4.9 → 1.9 ms、1000 段 8.5 → 2.1 ms、2000 段 23.5 → 3.2 ms；2 倍段落耗时 2.1 → 3.2 ms（≈1.5×，剩余为每趟 O(段落数) 的键扫描与状态提交）。
- **M2f 含控件文档（2026-10-21）**：每 20 段一个控件的正文，中段单次编辑（命令 + 布局）中位 500 段 1.7 ms、1000 段 2.2 ms、2000 段 3.6 ms；同规模全量布局 61 / 93 / 233 ms（≈3%）。此前控件让 `canIncrementalPagination` 直接返回 false，每次编辑都是全量。
- 同期 `TextMeasurer` 去掉超线性（LRU O(1) + 缺字检测记忆化）：首次布局 1000 段 346 → 121 ms、2000 段 1265 → 255 ms（2 倍段落 2.1×）。
- **端到端击键**（命令 + 布局 + 渲染 + 命中索引，Editor 级，2026-10-20）：中段连续单字输入中位数 500 段 2.2–2.4 ms、1000 段 3.1–3.5 ms、2000 段 5.6–6.6 ms；行数变化（一次插入 100 字）回落 M2b 续排：5.1 / 14.9 / 39.8 ms，仍远低于同规模全量（2000 段约 255 ms）。正常输入只在换行点触发这条路（约每行一次）。
- 目标「增量 ≤ 全量的 25%」已达成。

### 4.3 回归

- 既有 200 个测试文件 / 2260 条用例（2259 passed + 1 skipped）全绿（2026-10-21）。
- 导出（JSON/TXT/HTML/OFD/CDA/元素）结果不变 —— 它们读的是同一份 SLIF/文档投影。
