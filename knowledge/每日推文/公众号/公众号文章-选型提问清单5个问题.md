# 电子病历编辑器怎么选？先问这 5 个问题再谈价格

> 选型最贵的一课不是"买贵了"，而是买完才发现——它做不了你真正要的那件事。

"这份病历编辑器能导出 Word 吗？"

这个问题，如果在**报价之后**才问，往往已经晚了。

大多数选型会开成"功能表朗读会"：对方念一遍支持列表，你记一遍关键词，然后进入价格环节。但真正决定这个项目半年后会不会返工的，是另外几个问题——**它们不在报价单上，也很少有人主动讲**。

下面这 5 个问题，建议按顺序问。每一个都能当场验，也都有"听起来没问题、其实是坑"的回答。

## 一、为什么先问这 5 个，而不是先看功能表

功能表是**平权**的：所有方案都能勾上"支持模板""支持表格""支持打印"。

差别在**同一句话背后的实现深度**。"支持打印"可以是"把内容丢给浏览器打印"，也可以是"预览的第 3 页和打印的第 3 页逐字一致"——这两件事在报价单上长得一模一样，在质控科翻你病历的时候差得很远。

所以这 5 个问题的设计逻辑是：**每一个都指向一个"做不深就一定会露馅"的能力**，而且都能用一份真实文档当场验。

## 二、问题 1：分页是"按纸张算"的吗？打印出来和预览一样吗？

**为什么问这个。** 病历最终是要打印、签字、归档的。而网页富文本天生是**流式**的——内容有多长，页面就往下长多长；分页是后加上去的。这就导致一个常见结果：屏幕上好好的，打出来页码错位、页脚丢失、跨页表格第二页没有表头。

**怎么当场验。** 不要看演示文稿，要一份**跨页的长表格**（比如检验单），做两件事：

1. 在应用内预览，翻到第 3 页，记住页脚写的是"第 3 页 / 共 N 页"；
2. 直接打印，翻到纸上的第 3 页，比对页脚与内容断点。

**危险信号。** 回答停留在"我们支持打印""支持 A4"；或者演示时只给你看一屏内容，不给你看跨页。

**我们这套的答案。** 分页是一个**纯函数**：同样的文档 + 同样的页面设置，永远得到同样的分页结果；打印时**复用同一条渲染管线**，所以"预览第 3 页"和"打印第 3 页"是同一批页面图。跨页表格会自动重复表头，段落被拆到两页时两侧各留至少 2 行（孤行寡行控制）。这条链路的细节，系列第 16 篇《病历编辑器怎么保证"打印出来和预览一模一样"》讲透了。

## 三、问题 2：字段是"结构化"的，还是藏在 HTML 里的？

**为什么问这个。** 病历里的"血压""诊断""用药"不是随便一段文字——它们要能被**程序读出来**：质控规则要扫描它们，病案编码要提取它们，科研要统计它们。如果字段只是一段带样式的文字，那所有下游能力都得靠正则去猜。

**怎么当场验。** 让对方**导出一份 JSON**，然后问一句："这个字段，在 JSON 里是它自己的一个节点，还是只剩一段文字？"

**危险信号。** 字段在导出结果里是"带样式的 span"，或者需要靠关键词匹配才能定位；再或者——**导出里根本没有结构化数据**，只有纯文本。

**我们这套的答案。** 文档模型有 **16 类节点**，结构化录入控件（**8 类**：文本 / 多行文本 / 数字 / 下拉 / 日期 / 日期时间 / 复选框 / 单选框）本身就是独立节点，不是样式模拟出来的。导出的 JSON 是**完整文档树序列化**，还带目录（`_toc`）与内容溯源标识——字段在导出里仍然是字段。

## 四、问题 3：导出到底支持什么？PDF / Word 现在有没有？

**为什么问这个。** 这是最容易被"话术"糊过去的一题，也是最容易写进合同后翻车的一题。因为大部分医院的最终归档是 Word / PDF，所以这个问题一旦回答含糊，验收时必然扯皮。

**怎么当场验。** **打开导出对话框，自己看。** 能点的、灰的，一目了然——不要只听介绍，更不要接受"即将支持"作为合同条款。

**危险信号。** 把"规划中"说成"马上就有"；或者用"我们支持打印 PDF"来模糊"能不能导出 PDF 文件"。**打印和导出 PDF 是两件事**：一个是把页面图交给打印机，一个是生成可再编辑/可归档的 `.pdf` / `.docx` 文件。

**我们这套的答案。** 当前可用导出格式是 **JSON / TXT / HTML**，另外**页面打印（Canvas 页面渲染后打印）已经可用**。**PDF / DOCX 导出属于规划中，现在确实没有**——这条我们在每篇文章里都如实写着，不在合同里给时间承诺。

## 五、问题 4：上万字的病历，打开和编辑会不会卡？

**为什么问这个。** 门诊一天几十份病历，住院病程天天写。编辑器慢 200ms，医生一天就要多等几分钟；慢到转圈，医生就会开始"先写在纸上，回头再录"——那这套系统就白做了。

**怎么当场验。** 拿一份**真实的三十页以上病历**（不要用演示用的短文档），让对方现场做四件事：打开、连续输入一段话、快速滚动到底再滚回来、按 Ctrl+Z 撤销。

**危险信号。** 只演示短文档；或者被问到"为什么不卡"时，答不出机制，只有一句"我们做过性能优化"。

**我们这套的答案。** 六个具体机制：只画可见页（视口虚拟化）、一帧只画一次（rAF 合并）、只清变化的那一小块（脏区裁剪）、改一个字只重排那一段（增量排版）、脏区三层自动追踪、连续输入 500ms 合并成一步操作。另外内置了性能埋点（渲染帧耗时 / 布局耗时 / 击键延迟 / P95）——但要如实补一句：**埋点需要显式接入上报地址才会开始采集，缓存命中率统计目前还是占位值**。

## 六、问题 5：能不能改？改完留不留痕？

**为什么问这个。** 这一题对应的是**审计**。质控科最常问的一句话是："这份病历第 3 页的诊断，是谁改的？什么时候改的？改之前写的是什么？"——答不上来，就要靠翻纸质、打电话、问当事医生去拼时间线。

**怎么当场验。** 两个具体动作：让对方**调出某一版历史文档和当前版本做比对**；再问一句"**归档之后，还能不能改**"。

**危险信号。** 只有一张"操作日志表"的表结构，没有可用的查询界面；或者对"归档后能不能改"的回答是"可以，有权限就行"。

**我们这套的答案。** 已经能做到的：**文档比对**（两版差异计算 + 可视化，路由形如 `/compare/:oldId/:newId`）、**版本管理**（历史版本可回溯）、**批注**（带线程与文本范围，可展示 / 回复 / 解决）、**只读与打印模式**（归档态锁死编辑，只能看、只能打）。**还没接上的也一并说清**：修改留痕（track changes）目前只到"渲染"这一步——三种语义的着色已经就绪，但**产生修订标记的编辑流程没有接入**；审计日志**只有实体与数据访问层，没有"每次操作自动写一条"的拦截器**；批注面板**还没有"新建批注"的交互入口**。

## 七、问完这 5 个问题，再谈价格

价格不是不重要，而是**它只有在能力对齐之后才有意义**。

同一个"病历编辑器"，三条路线的成本结构完全不同：

| 路线 | 你买到的是什么 | 主要成本付在 | 能力上限由谁决定 |
|---|---|---|---|
| 商业套件 | 确定性（成熟度 + 履约兜底） | 授权 / 年费 + 供应商绑定 | 厂商的 Roadmap |
| 开源内核 | 起点（不必从 0 开始） | 二次开发与长期维护人力 | 你团队的上限 |
| 自研 | 上限与可控 | 时间 + 一支核心团队 | 你的业务深度 |

一句话：**商业套件把不确定性换成钱，开源内核把不确定性换成人力，自研把不确定性换成时间。** 至于"你这类团队该走哪条路"，那是另一个问题——已经写在《病历编辑器选型地图》里了，这篇不重复。

**先问清楚"它能不能干成这件事"，再谈"它值多少钱"。** 顺序反了，省下的那点钱，通常会在返工里加倍还回去。
