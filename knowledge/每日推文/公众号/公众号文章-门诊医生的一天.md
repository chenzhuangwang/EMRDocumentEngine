# 门诊医生的一天：40 个病人里，有多少时间在写病历

> 这篇不给统计数字——它给一个"明天就能自己做"的数一数的方法。

门诊结束，你记得今天看了 40 个病人。

但你说不清，其中多少时间花在"写"上。

不是因为没有时间统计工具，而是因为**"写病历"这件事从来没有被单独计过时**——它混在问诊、查体、开单、叫号之间，一段一段地发生，每段几十秒，加起来却是一天里最长的那块。

**先把口径说清楚。** 市面上"医生 XX% 的时间花在写病历"这类说法口径很多，但**我没有可复核的数据源**，所以这篇一个统计数字都不引用。这篇真正能拿出来的，是把"写病历"拆成**可数的动作**，然后回答两个问题：**哪几个动作是工具能替你回收的，哪几个回收不了。**

标题里的"40 个病人"是门诊场景设定，不是统计结论。

## 一、把"写病历"拆成 5 个动作

"写病历慢"是个笼统的说法。拆开看，它其实是五件不同的事：

| 动作 | 你实际在做什么 | 工具能回收吗 |
|---|---|---|
| **打模板段** | 主诉、现病史、既往史、系统回顾——大半是重复结构 | ✅ 能（模板 + 结构化控件） |
| **敲缩写** | `i.v.g.t.t.`、`q.d.`、`Bp`、`SpO2` | ✅ 能（医学缩写自动更正） |
| **填已知信息** | 日期、时间、页码、标题、作者 | ✅ 能（动态域代码） |
| **找位置** | 上次写到哪、那个书签在哪、第几页 | 🟡 部分能（查找替换 / 书签 / 交叉引用） |
| **判断与表达** | 这一次的病史该怎么写才准确 | ❌ 不能，也不该被回收 |

这个拆法有个好处：**每一行你都能自己数。** 后面第五节给了一个两分钟就能做完的自测。

## 二、第一笔：打字的重复

门诊病历里最耗人的不是"写字"，是**反复写同一段结构**。

这套引擎的应对是**模板**：公共模板 + 私有模板，一键套用；模板里存的不是"一段固定文字"，而是**结构**——哪些字段、什么类型、能不能改。模板被拆成四层（语义 / 运行时值 / 模板设计期 / 表现），各管一件事。

配合的是**结构化录入控件（8 类）**：文本 / 多行文本 / 数字 / 下拉 / 日期 / 日期时间 / 复选框 / 单选框。

这里有个容易被忽略的区别：**下拉框和复选框省下的不只是字数。**

- 你少敲了几个字——这是最表层的好处；
- 更重要的是，**这一格从此"可被程序读到"**。它不再是一段带样式的文字，而是文档树里一个独立的节点。质控要扫描它、编码要提取它、统计要汇总它，都不需要靠关键词去猜。

反过来，如果字段只是"一段看起来像字段的文字"，那所有下游能力都只能靠正则硬猜——**省下的那几秒，会在别的地方加倍还回去。**

## 三、第二笔：缩写的重复

门诊里高频出现的，是一批"打起来很别扭、读起来很标准"的缩写。

引擎内置了一份医学缩写词库，**共 25 条**，输入后触发匹配、自动替换。举几条实际的：

- **给药途径**：`i.v.g.t.t.` → 静脉滴注、`i.v.` → 静脉注射、`i.m.` → 肌肉注射、`i.h.` → 皮下注射、`p.o.` → 口服；
- **频次**：`q.d.` → 每日 1 次、`b.i.d.` → 每日 2 次、`t.i.d.` → 每日 3 次、`q.i.d.` → 每日 4 次、`q.o.d.` → 隔日 1 次、`q.n.` → 每晚、`q.m.` → 每晨、`p.r.n.` → 必要时、`s.t.` → 立即；
- **常见指标**：`Bp` → 血压、`HR` → 心率、`RR` → 呼吸频率、`T` → 体温、`SpO2` → 血氧饱和度、`WBC` → 白细胞计数、`Hb` → 血红蛋白、`PLT` → 血小板计数。

两个细节值得单独说，因为它们决定了这东西**能不能放心用**：

1. **全词匹配**：触发词前后必须是空白、标点或行边界。否则 `T` 这种单字母缩写会误伤正常单词——那就不是省事，是制造事故。
2. **大小写敏感**：`Bp`、`HR`、`T`、`SpO2` 这类要求大小写完全一致才替换。**宁可漏替换，不可错替换。**

词库本身是可配置的——科室有科室的习惯缩写。

## 四、第三笔：已知信息的重复录入

有一类信息，系统**本来就知道**，却常常要人手填：日期、时间、页码、总页数、文档标题、作者、保存日期、打印日期。

引擎把这 8 类做成了**动态域代码**——**共 8 种**。

域和"填进去的字"的区别在于：**域是会跟着变的。**

- 页码是域：增删内容后，页码自动重排，不用手改；
- 打印日期是域：打印那一刻取当前时间，不是上次手填的那天。

这挡掉的是一类很典型的错误：**昨天填的日期，今天忘了改。** 这种错不会报错、不会崩，只会安静地留在病历里。

## 五、还有一笔隐性的：找

门诊场景里，最容易被忽略的一笔时间是"翻来翻去"：上次写到哪了、那个书签在哪、上次那个诊断在第几页。

这一笔工具只能部分回收：查找替换（含页眉页脚区域）、书签、交叉引用、目录（导出的 JSON 里带 `_toc`）。

**它回收不干净**——因为"找"往往是因为**写的时候没想清楚**，而不是因为工具不好用。这一点得认。

## 六、回收不了的部分，也说清楚

写到这里必须停一下，否则就成了功能宣讲。

**工具不该碰的部分**：病史采集、临床判断、个体化表达。这些是病历的**价值本体**，任何"帮你自动生成"的承诺都要小心——一份不准确的病历，比一份慢的病历危险得多。

**工具自己还没做到的部分**，一并说清：

- **自动查漏，现在还不该指望它。** 引擎里有质控规则引擎（**6 条内置规则**，支持自定义扩展），但它在整个仓库里**从未被实例化，对应的结果面板也从未被渲染**——能力写好了，界面够不着。
- **修改留痕只到"渲染"这一步。** 插入 / 删除 / 修改三种语义的着色已经就绪，但**产生修订标记的编辑流程没有接入**。
- **PDF / Word 导出仍未实现**，当前可用导出格式是 JSON / TXT / HTML（另加页面打印）。

**能救命的那一条，是真做到了**：自动保存——**3 秒防抖**触发、环形保留**最近 3 个版本**、页面加载时**检测残留数据并提示恢复**。但它只保护"不丢"，不保护"写得对"。这两件事不能混为一谈。

## 七、一个明天就能做的自测

不用等工具给你出报告。**门诊结束时，花两分钟数四个数：**

1. 今天有几条既往史是**重新打**的？
2. 有几个缩写是**手敲全称**的？
3. 有几次**日期或页码是手填**的？
4. 有几次为了找一个东西**翻了三页以上**？

这四个数不需要任何统计工具，你自己数得出来。数完之后你会知道：**该先改哪一个**——而这比任何"行业平均"都有用，因为它是**你自己的账**。

## 八、回到场景

"写病历慢"，通常不是打字慢，是**重复动作太多**。

重复动作的特点是：单次只花几秒，所以你不觉得是问题；一天下来几十次，加起来就是一天里最长的那块。

**工具的职责不是替你判断，而是把重复的从你手里拿走。** 剩下的那部分——想清楚这次该怎么写——本来就该是你的时间，不该被"再敲一遍"挤掉。
