QUOTE

值班的病历不是“写得多”，是接得上、找得到、断不了。

国庆值班有个特点：人少、事杂、随时被打断。

门诊有排班，病房有交接；但假期值班，常常是一个人守几个病区——一边处理临时情况，一边还得把记录补齐。平时可以一口气写完的病历，值班时会被切成十几段。

这篇短一点，只讲值班场景下的三个约束，以及工具能帮上什么、帮不上什么。

口径先说清：这套引擎是一套通用的病历文书编辑内核，不是值班专用工具。全文不引用任何行业统计数据——讲的是约束，不是平均值。

01

THREE CONSTRAINTS

值班的三个约束

约束 具体表现 工具能帮上什么
随时被打断 写到一半被叫走，回来接不上 自动保存（3 秒防抖 / 最近 3 版 / 崩溃恢复检测）
一个人扛多个病区 找病人、找上次记到哪、找那个关键指标 查找替换 / 书签 / 交叉引用 / 目录
要交给下一个人看懂 交班不是“写完就行”，是“别人能接上” 模板 + 结构化字段（关键指征可一眼扫到）

三个约束里，第一个是值班独有的；后两个平时也有，只是值班时被放大。

02

THE INTERRUPTION

“随时被打断”：值班最真实的约束

平时写病历，你可以一口气写完再走。值班不行——记录是断着写的。

所以“别丢稿”这件事，在值班场景里不是锦上添花，是底线。引擎的自动保存是这样工作的：


3 秒防抖触发

你停手 3 秒，它就存一次，不用你点保存。


环形保留最近 3 个版本

不是只留最新一份，前两版还在。


加载时检测残留数据

上次没正常关闭，下次打开会问你要不要恢复。

「它保护的是“不丢”，不保护“写得对”——自动保存救得了断电，救不了漏记。」

03

THE SEARCH COST

“一个人扛多个病区”：找的成本被放大

值班时，“找”的次数是平时的几倍：找病人、找上次记到哪、找上一班留的那句话、找那个关键指标在第几页。

工具能帮上的：查找替换（含页眉页脚区域）、书签、交叉引用、目录（导出的 JSON 里带 _toc）。

但这一笔它回收不干净：工具只能减负，替代不了结构设计。

因为“找”花掉的时间，多半是“写的时候没想清楚结构”欠下的——该做成模板的没做，该拆成字段的写成了叙述。

04

THE HANDOVER

“交给下一个人看懂”：交班其实是个读者问题

交班的读者是同事，不是你自己。

同一件事，你写的时候自己懂，别人接手时可能要猜——而值班交接最怕的就是“猜”。这里有两件事能帮上：


结构化字段

下拉、复选框、日期这类控件，让关键指征可被一眼扫到，而不是埋在一段叙述里。它省下的不只是敲字，更是“读完才知道有没有”的那几秒。


模板

把“每次都要重来一遍”的部分提前定死。这也是“科室经验沉淀”的一部分——值班最怕的不是忙，是每个人写法都不一样。

05

THREE DISCLOSURES

三件事必须提前说清

值班场景下，这三条尤其要紧，所以放在前面：

1

这是桌面产品，移动端不适用。床边随手记、扫码这类场景不是它的强项。如果值班流程强依赖手机在床边完成记录，正确的做法是分工：桌面端负责集中录入、整理、打印、归档，床边即时记录交给移动端系统，两边以数据对接。

2

“自动查漏”现在还不该指望它。引擎里有质控规则引擎（6 条内置规则，支持自定义扩展），但它在整个仓库里从未被实例化，对应的结果面板也从未被渲染——能力写好了，界面够不着。

3

“改动留痕”只到一半。插入 / 删除 / 修改三种语义的着色已经就绪，但产生修订标记的编辑流程没有接入。值班期间如果多人经手同一份病历，别指望它自动标出“谁改了哪一处”。

06

COUNT THREE

值班结束后，花两分钟数三个数

1

今天有几次是写到一半被叫走的？

2

有几次是翻回去找“上次记到哪”的？

3

交班时，有没有因为写法不一样，多解释了几句的？

第三个最值得记。前两个是环境造成的，第三个是模板该补了的信号——它说明你们科室对同一件事有不止一种写法，而下一个人每次都要重新理解一遍。

∞

THE END

写在最后

值班的负担，很少来自“写得多”，多半来自“接不上、找不着、说不清”。

工具能做的，是把“每次都要重来一遍”的部分固定下来；剩下的那部分——这个病人的情况该怎么判断、该怎么描述——本来就该是值班医生的判断，不该被“再敲一遍”挤掉。

祝各位值班顺利，别丢稿。
