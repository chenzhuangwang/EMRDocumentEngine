## 0. 契约总则

### 0.1 本契约解决什么问题

项目已完成一年独立开发，编辑器内核与工程闭环完整，并已产出 5 篇原创公众号文章，但**账号仍处于冷启动状态**：

**账号现状（真实数据，详见 [1.6](#16-公众号账号事实基线)）**

```
累计关注 12 人   ·   原创 5 篇   ·   近 30 天阅读 592 人   ·   近 30 天新增关注 10 人
流量来源：推荐 88.3% ｜ 聊天会话 5.4% ｜ 公众号主页 4.1% ｜ 搜一搜 1.5%
```

**瓶颈不在内容供给，也不在渠道覆盖，而在"看完即走"**，具体三层：

1. **关注转化断裂**：近 30 天有 592 人阅读，却只新增 10 关注（转化率 ≈1.69%）。5 篇文章**均无关注引导模块**，读者读完后没有任何"留下来"的理由与动作；
2. **流量结构单一**：推荐流占 88.3%，而搜一搜仅 1.5% —— 意味着**没有搜索长尾沉淀**，一旦推荐流波动，增长立即停摆；
3. **私域无承接**：无关注自动回复、无往期精选、无留言互动机制，读者与账号之间是一次性关系，无法形成复利。

本契约将上述问题转化为乙方可执行、可验收的职责。

### 0.2 约束优先级（冲突时的裁决顺序）

```
1. 事实真实性      — 任何宣称必须有代码/仓库事实支撑
2. 合规与平台规则   — 不刷量、不诱导关注、不违规互关
3. 目标达成        — 粉丝增长

```

### 0.4 渠道口径说明（执行前必须知晓）

> 公众号「旺de碎碎念」是本项目**唯一的推广渠道，也是唯一的验收落点**；主仓库托管在 Gitee（`https://gitee.com/wangwang_1_1665527118/emrdocument-engine`），线上 Demo 为 `http://139.196.151.15/`。**Gitee 与 Demo 只作为文章中的可信度背书出现，乙方不对其做任何独立的推广动作，也不对其设定任何增长指标。**

**本版只聚焦公众号一个渠道，理由如下：**

1. **主要矛盾在转化，不在渠道数**：账号累计关注仅 12，关注转化率仅 1.69% —— 这是"内容 → 关注"链路没接通，与渠道数量无关；
2. **站内转化尚未收口**：5 篇文章**均无关注引导模块**，此时新增外部渠道，只会把流量导进一个漏水的桶；
3. **站内仍有三个未开采的入口**：搜一搜长尾（1.5%）、存量文章的持续曝光、往期精选承接 —— 先把这三件事做透，投产比远高于铺开渠道。

> **因此，v2.0 中的掘金 / 知乎 / CSDN / SegmentFault / V2EX / B 站 / 社群 / 小红书 / X 等渠道约定及其 KPI 全部作废。** 若未来站内关注转化率稳定在 3.0% 以上、且发布节奏稳定，再由甲方提出、按第 11 条变更后重启多渠道，届时另行补充渠道章节。

**必须正视的微信平台特性**：

- 推荐流（看一看 / 推荐）是当前最大流量来源（88.3%），但**算法不可控**，不能作为承诺依据；
- 微信对**诱导关注**（如"关注后可见全文""转发集赞领资料"）有明确处罚，一旦触发轻则限流、重则封号；
- 关注是可逆的：内容跑偏会带来**取关**，里程碑净增目标已预留该损耗（见 3.2）。

### 3.2 漏斗反推：为什么最短是 90 天

**第一步：先算清楚"按现状走"会怎样**

```
当前速率：592 阅读/月 × 1.69% ≈ 10 新增关注/月
扣掉自然取关（约 30%）        ≈ 净增 7 人/月
按现状跑 90 天  ≈ +21   →  期末 33   ❌
按原 180 天跑   ≈ +63   →  期末 75   ❌（180 天同样不达标）
```

**结论：光靠"多发几篇"或"把时间拉长"都不行，必须同时撬动"阅读量"与"关注转化率"两个变量。**

**第二步：达成速度由月阅读量决定**（净增 ≈ 月阅读量 × 关注转化率 × 70%）

| 月阅读量 | 关注转化率 | 月净增 | 达成 100+ 所需 |
|---|---|---|---|
| 592（现状） | 1.69% | ~7 | ~12.6 个月 |
| 592 | 2.5% | ~10 | ~8.5 个月 |
| 1,200（约 2 倍） | 2.5% | ~21 | ~4.2 个月 |
| **1,600（约 2.7 倍）** | **3.0%** | **~34** | **~2.6 个月 → 取 90 天为下限** |

**第三步：90 天目标路径反推**

```
内容曝光 / 触达 (~140,000)          ← 推荐流放量 + 搜一搜长尾 + 存量文章持续承接
   ↓  进入阅读 ~3.4%
文章阅读人数累计 (4,800)             ← 基线 592/月 → 90 天均值 ~1,600/月
   ↓  关注转化率 3.0%（基线 1.69%）   ← 靠"关注引导模块 + 系列化内容"
新增关注 (~143)
   ↓  自然取关 + 未成年人/僵尸清理（按 ~30% 折算）
净增关注 (~100)
   ↓
累计关注 12 + 100 = 112  →  ✅ 达成 100+
```

**为什么再短做不到（60 天不成立）**：流量爬坡有硬顺序 —— D1–14 只能靠 5 篇存量文章"原地转化"（没有增量流量）；D15–45 搜一搜才开始沉淀、完读率优化才开始影响推荐权重；D46–90 才具备"系列专栏 + 破圈文"的冲量条件。要在 60 天内净增 88 人，等于要求月阅读量在第一个月就翻 4 倍以上，不现实。**90 天是数学与爬坡节奏共同决定的下限。**

**日更在 90 天路径里的位置**：日更把 90 天的原创供给从 ~25 篇提到 **~85 篇**，是**唯一完全由乙方控制**的变量 —— 它为"月阅读 2.7×"提供了内容基数，也缩短了搜一搜长尾的收录周期。但日更要被理解为"输入"而不是"捷径"：**90 天下限由推荐权重累积与转化率爬坡的"时间常数"决定**，稿件再多也不能把算法爬坡压缩。反过来，若为凑日更降低单篇质量，完读率下滑会直接反噬推荐权重（N9 / N10）—— 所以日更必须配套**质量红线**（5.1）与**选题蓄水池**（7.2）：**宁可少发一篇，也不发低质充数稿。**

**关键假设与风险**：

- 90 天是**最短路径，不是自然可达**：它要求月阅读量在 90 天内提升约 **2.7 倍**（592 → 末月 ~1,600），且关注转化率做到 **3.0%**；
- 关注转化率从 1.69% → 3.0%（+78%）**必须靠 CTA 模块与内容系列化实打实做出来**，不是自然发生的；若第 45 天仍 < 2%，按 8.4 节触发专项复盘并启动顺延评估；
- 流量爬坡依赖推荐流；若推荐流下滑，只能用**搜一搜长尾 + 存量文章的持续曝光**补位 —— 本版没有外部渠道兜底，**站内长尾的优先级因此高于 v2.0**（这正是把"搜一搜占比 ≥10%"设为核心指标的原因）；
- 漏斗每一环必须在第 8 章可量化追踪，**不允许用"感觉有效"替代数据**。

**日更的三条质量红线**（与"日更不降质"绑定，违反即视为未达标）：

1. **事实优先于节奏**：任何一天若找不到能通过第 1 章口径自检的选题，**宁可从蓄水池顺延或发"轻量但真实"的短稿**（如真实踩坑复盘、留言问答），也**不得**用 AI 拼接、搬运、标题党凑数（N9 / N10 / R1）；
2. **组件不漏挂**：日更再快，每篇的**关注引导 + 往期精选**（附录 B.2）与关键词（1 主 + 3 长尾）**必须挂齐**，不得"先发了再补"；
3. **单篇标准不降低**：仍须满足 1,500–2,500 字、钩子开头、每 300 字小标题、正文 ≥2 张图（或 5.4 占位）—— 篇幅可因题材浮动，但**结构不省略**。

### 5.2 公众号站内四个流量入口与打法

> 依据 1.6 的阅读来源数据：推荐 88.3% · 聊天会话 5.4% · 公众号主页 4.1% · 搜一搜 1.5%。四个入口的**可控性差异极大**，必须区别对待 —— 可控的先做透。

| 入口 | 现状 | 可控性 | 本契约打法 |
|---|---|---|---|
| **推荐流**（看一看 / 推荐） | 88.3% | 低（算法决定） | 不直接操作，只通过**完读率 + 在看/分享**间接撬动（见 5.2.1） |
| **搜一搜** | 1.5% | **高** | 关键词布局，把每篇文章变成可被检索的长尾资产（见 5.2.2） |
| **存量文章** | 未统计 | **高** | 给 5 篇存量文章补挂关注引导（见 5.2.3） |
| **会话 / 主页 / 名片分享** | 5.4% + 4.1% + 名片 10% | 中 | 往期精选 + 自动回复承接（见 5.2.4） |

#### 5.2.1 推荐流：间接撬动，不做"技巧"

- 推荐权重的主要输入是**完读率、在看、分享、收藏**，其次是发布稳定性；
- 具体动作：**钩子开头（前 3 行）**、篇幅控制在 1,500–2,500 字、每 300 字一个小标题、正文至少 2 张图；
- **固定节奏发布**（**日更；发布时段硬性固定为每日 12:00 前后，窗口 11:30–12:30**），该时段为硬性规则，不得随意更改或漂移（如 17:00、19:30 等），避免长期断更或时段漂移拉低账号活跃权重；
- 红线：**不做标题党**（N9）—— 短期点击换不来完读率，反而伤权重。

#### 5.2.2 搜一搜：性价比最高的动作

- 现状：搜一搜只带来 1.5% 的阅读，却贡献了 20% 的涨粉 —— **效率最高但几乎没做**；
- 每篇文章必须确定 **1 个主关键词 + 3 个长尾词**，并出现在**标题、首段、小标题、摘要**中；
- 关键词来源：搜一搜下拉词、后台"搜索来源"词、读者留言中的提问原话；
- 目标：搜一搜来源占比 1.5% → **≥10%**（3.1 核心指标）。

#### 5.2.3 存量文章改造（M1 最高优先级动作）

> **存量文章仍在被推荐流分发，是当前最便宜、最确定的一块转化位。**

1. 逐篇核对 5 篇文章（[公众号/](file:///d:/czw/EMRDocumentEngine/knowledge/%E6%AF%8F%E6%97%A5%E6%8E%A8%E6%96%87/%E5%85%AC%E4%BC%97%E5%8F%B7)）是否已挂关注引导模块；
2. 未挂的全部补挂（附录 B.2），并统一补齐"往期精选 3 篇"；
3. 复查标题与首段的关键词覆盖，必要时做**小幅优化后重新推送**；
4. 改造完成后出**改造清单 + 改造前后关注转化对比**（交付物 D3）。

#### 5.2.4 会话 / 主页 / 名片：把"路过的读者"接住

- **往期精选**（文末固定模块）：让新读者有"下一站"，降低取关；
- **关注后自动回复 + 自定义菜单**（需授权，见 4.4）：一句话说清"这个号写什么 + 从哪篇开始读"；
- **名片分享**（当前贡献 10% 涨粉）：在文末提供自然的"转发给同事"动作，**不得**使用集赞 / 截图领取等诱导形式。

### 5.3 日更节奏（周循环模板）

> **日更 = 每天 1 篇原创，周末不断更。** 单日产能靠"**选题蓄水池 + 提前一天成稿**"保障，而不是当天从零开始（蓄水池机制见 7.2）。
> **配图随稿走，不堆到周末。** 每篇稿件的配图在**发布前一天**完成（或按 5.4 写占位提示词后照常发布）。

| 时段 | 内容 / 运营动作 | 转化与配图动作 |
|---|---|---|
| 每日 · 上午 | **当日稿件定稿**：主关键词 + 3 长尾词核对、事实自检（对照第 1 章口径）、排版 | 封面 + 正文 ≥2 张配图到位（缺口按 5.4 写占位） |
| 每日 · 发布时段（**硬性固定 12:00 前后，窗口 11:30–12:30**） | **发布**（固定时段，稳定推荐权重）；发布后 2 小时内守留言 | 检查引导模块 + 往期精选在手机端的渲染 |
| 每日 · 下午 | 从蓄水池写**次日稿件初稿**；把高价值留言转为选题 | 补拍真实截图 / 录制 GIF |
| 每日 · 晚间 | 留言深度互动；往期精选复投、存量文章改造推进 | 仅做归档与复用：更新可复用素材库（附录 A.3） |
| **每周五** | **数据采集（公众号后台）+ 周报 + 下周 7 篇选题会**（见 8.3） | 核对下周 7 篇的配图与引导模块是否到位，缺口写入 D5 |

### 5.4 配图占位规范（文生图提示词）

配图不能即时产出（无真实截图 / 无作图工具）时，**不允许稿件停在"⬜ 待制作"**，必须先写入占位说明，再走发布流程。占位格式：

```
📷 配图位 ①｜类型：{实况类 / 示意装饰类 / 架构图}
画面内容：{一句话描述，说明这张图要证明什么}
文生图提示词：{可直接投喂文生图模型的英文 prompt，含主体 / 风格 / 构图 / 画质词}
尺寸建议：{square_hd / portrait_16_9 / landscape_4_3 / landscape_16_9}
来源：{真实截图 / AI 生成 / 自绘架构图}
```

**三类配图的占位方式不同（与附录 A.3「禁止与实际产品不符的示意图」约束一致）：**

| 类型 | 能否 AI 生成 | 占位要求 |
|---|---|---|
| 实况类（产品界面、控件录入、质控提示、GIF） | ❌ 不可 | 写「截图 / 录制需求说明」：界面状态、必须体现的元素、需高亮区域；由甲方或人工补拍 |
| 示意 / 装饰类（封面图、概念示意、流程示意） | ✅ 可 | 写可直接使用的文生图提示词 + 尺寸，生成后即可入稿 |
| 架构图 | ✅（优先自绘） | 优先自绘以保证准确性；文生图仅用于风格底图 |

> **红线**：AI 生成的图片**只能用于示意 / 装饰**，不得冒充产品真实界面（N8 / 附录 A.3）。

## 6. 留言互动与私域运营

### 6.1 留言运营

| 事项 | 规则 |
|---|---|
| 精选标准 | 优先精选**能引发同行共鸣或补充信息**的留言，不选空泛"已关注" |
| 响应 SLA | 发布后 **2 小时内**回复首批留言；工作日 12 小时内回复新留言 |
| 回复姿态 | 先致谢 → 再给答 → 必要时引导到文章 / 仓库 / 私信 |
| 选题转化 | 高价值提问脱敏后写成下一篇文章（呼应 S3），并在文中回应该读者 |
| 反引流 | 对明显广告 / 导流留言不精选、不回复 |

### 6.2 关注引导与欢迎语

- **关注后自动回复**（需授权，见 4.4）：一句话说明"这个号写什么" + "从哪篇开始读" + 往期精选入口；
- **自定义菜单**（需授权）：建议三项 —— 「往期精选」/「开源项目」/「联系我」；
- **名片分享**：当前贡献 10% 涨粉，鼓励作者在文末提供"转发给同事"的自然动作（**不得**用集赞、截图领取等诱导形式）。

### 6.3 读者社群

- 视甲方意愿建立交流群（甲方确认），承接"非留言类"问题；
- 乙方负责：常见问题沉淀为 FAQ、整理重复问题、引导提问规范；
- 甲方负责：技术判断、承诺口径。

> 注：读者社群属于**公众号私域的延伸承接**，不作为独立推广渠道，不设引流指标。

### 6.4 正向循环设计

```
好内容 → 推荐流曝光 → 阅读
   ↑                     ↓  （关注引导模块）
   └── 脱敏成文 ←── 留言提问    关注（+1）
                                  ↓
                            持续更新 → 复访 → 在看/分享 → 撬动推荐
```

这是本契约**唯一被鼓励的"增长飞轮"**：增长来自"读者真的想继续看"，而非营销话术或互关换粉。

### 7.3 单篇内容生产 SOP

```
1. 选题      → **从选题蓄水池取当日坑位**（见 7.2），明确"给谁看 / 解决什么困惑"；取出即登记消耗，每周五补池至 ≥14 篇
2. 关键词    → 确定 1 个主关键词 + 3 个长尾词（来源：搜一搜下拉、后台搜索来源、读者提问原话）
3. 事实核验  → 对照第 1 章事实基线，标注引用的代码文件与数字出处；账号数据注明统计区间
4. 结构      → 钩子(前3行) → 冲突/问题 → 拆解 → 截图/图表 → 结论 → 往期精选 → 关注引导
5. 配图      → 封面图 + 正文 ≥2 张（禁止纯文字长文）；无法即时出图时按 5.4 写占位
6. 自检      → 逐条核对 1.5 禁用清单 + 微信平台规则 + 关注引导模块是否挂上 + 关键词是否落到标题与首段
7. 发布      → 公众号发布，2 小时内守留言
8. 数据回收  → 24h / 72h / 7d 记录数据（重点看关注转化率、完读率、搜一搜来源），进入看板
```

### 7.4 系列化与站内复用

> 本契约只有公众号一个渠道，"复用"指的是**同一批事实资产在站内被反复利用**，而不是跨平台改写。

| 根内容类型 | 首次发布形态 | 站内复用方式 |
|---|---|---|
| 场景价值类 | 单篇长文 | 收入"往期精选"；相同痛点换角度再写（如"咽喉"→"时间去哪了"） |
| 内核深潜类 | 单篇技术长文 | 串成系列专栏（如"病历编辑器内核 12 讲"），文末互相串联 |
| 开发实录类 | 单篇复盘 | 沉淀为"踩坑合集"；数据好则追加同结构续篇 |
| 选型对比类 | 单篇盘点 | 随能力迭代定期更新重发，作为长期搜索入口 |

**复用原则**：同一观点在站内不同位置（主文 / 系列 / 精选）**重新组织标题与开头**，避免读者重复感；**每篇必须有新增信息**，不做原文重发。

| P | 上周目标与实际对比（重点：关注转化率、完读率） | 达成率表 |
| D | 记录本周发布与动作 | 发布清单 |
| C | 分析 Top1 / Bottom1 内容的**完读率与关注转化**差异原因 | 归因结论 |
| A | 决定加码 / 调整 / 停投 | 下周动作清单 |

**归因要求**：结论必须由数据支撑（如"W3 那篇挂着引导模块，关注转化 3.1%；未挂的篇均 1.6%，故全面补齐"），禁止主观判断。

### 8.4 止损与加码规则

| 触发条件 | 动作 |
|---|---|
| 关注转化率连续 3 周 < 1.5% | 专项复盘关注引导模块（位置 / 文案 / 是否被折叠），做 A/B 测试 |
| 完读率连续 3 篇 < 50% | 调整开头钩子、压缩篇幅、增加小标题与图表 |
| 搜一搜来源占比连续 1 个月 < 2% | 复盘标题关键词布局与历史文章的关键词覆盖，重做关键词清单 |
| 单篇涨粉 > 15 | 立即复用该选题结构，追加同系列（如"病历编辑器内核 12 讲"） |
| 单周取关 ≥ 2 | 检查内容是否偏离账号定位或更新断层，及时纠偏 |
| **连续 2 天未按日更发布** | 立即启用蓄水池应急稿（7.2）；若因选题枯竭，下周临时降配为 P3 / P1 为主并紧急补池 |
| 日更后完读率连续 3 篇 < 50% | 判定为"数量摊薄质量"，暂停加量，先改开头钩子与篇幅（5.1 质量红线） |
| 某类选题连续 3 篇关注转化 < 1% | 该选题方向降权，资源转向高转化选题 |
| 出现负面舆情（真实性质疑） | 立即暂停相关选题的推送，甲方确认后统一回应 |
| 账号被限流 / 警告 | 立即停止一切发布动作，比对 4.3 禁用项自查，整改后恢复 |

## 附录 B · 稿件标准结构与引导模板

### B.1 结构模板

```
[标题] 钩子式，含具体数字或反差（≤30 字），禁用标题党
[开头 3 行] 抛出真实场景痛点，不讲项目          ← 决定完读率
[正文] 问题 → 拆解 → 方案 → 代码/截图 → 结论
[诚实段] 明确未完成能力
[往期精选] 3 篇历史优质文章（固定模块）
[关注引导] 见 B.2                              ← 决定关注转化率
```

### B.2 公众号文末"关注引导 + 往期精选"标准模块

> **本模块为每篇公众号文章的必挂组件（R3）。** 需用公众号允许的内联样式实现（无 class / 无 script / 无 position），配色沿用红白色系。

```
──────────────
📌 往期精选
· {历史文章 1 标题}
· {历史文章 2 标题}
· {历史文章 3 标题}

如果这篇对你有用，欢迎关注「旺de碎碎念」
这里持续记录电子病历、医疗信息化与开源工程化的真实实践。
点个「在看」，让更多同行看到 ↓
──────────────
```

- **引导语备选**（按文章调性选用，**禁止**出现"关注才能看""集赞领取"等诱导表述）：
  1. `如果这篇对你有用，欢迎关注「旺de碎碎念」，下一篇继续聊病历编辑器的内核实现。`
  2. `这个号不追热点，只写电子病历与医疗信息化里真正踩过的坑。`
  3. `觉得有共鸣？点个「在看」，也欢迎在留言区说说你们医院的病历编辑器。`
- **通用结尾**：
  > 一份病历不该是医生的负担。让好的工具，成就更好的医疗。
